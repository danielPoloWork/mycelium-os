# ADR-0159: Keep the front door to what a first reader needs, and move the rest with its citations

- **Status:** Accepted
- **Date:** 2026-09-25
- **Deciders:** the maintainer (who filed roadmap 7.10, and chose on 2026-09-25 to move the
  judged sections and re-point their cases in one change) with the tech-lead (EADOS delivery
  agent)
- **Related:**

  judgements or the retriever, not both),
  [ADR-0053](0053-report-on-the-corpus-we-author-and-gate-on-the-one-we-do-not.md) (this

## Context

`README.md` reached **1 022 lines** by accretion. Every milestone added a section explaining
a decision it had measured, and each section was good on its own: *"Retrieval is lexical by
default, and that was measured"*, *"Nothing becomes verified without a gate and a person"*,
eighteen of them, then a Status section that retold Milestone 6's numbers. What a newcomer
needed — what this is, who it is for, how to install it, how to get to a first answer, where
the evidence is, how to contribute, how to report a vulnerability — was all present and all
buried: Install began at line 38, and the pointer to the security policy sat in a table on
line 1 015. The repository's *About* box, which a stranger meets before any of it, was empty.

Moving text out of a README would be an editing job anywhere else. Here it is not, because
**this repository's documentation is its own judged corpus**: the README is compiled, and the
judged case sets cite its sections by anchor. **Forty-five cases** — 20 of the frozen release
set, 23 of the dev set, 2 agent tasks — point into it, 28 of them at the eighteen sections that
had to move. A moved section is a broken citation, and the cases are generated by
`tools/build_eval_cases.py`, which refuses to write a set whose anchors do not resolve.

## Decision

**The README carries what a first reader needs, in the order they need it, and links to the
rest.** It opens with what the project is, who it is for, and the ten-minute path to a cited
answer (NFR-4), then Install, Try it, How it compiles, the comparison table, *Where the
evidence lives* — a table from each question a sceptical reader asks to the directory that
answers it — Status, Build, Contributing and reporting a vulnerability, the project's documents,
Inspiration, License. 1 022 lines become 274. Numbers are linked, not restated: the benchmark
reports are the marketing (spec 06 §4), and a number copied into the README is a number that
goes stale there first.

**The eighteen decision sections move verbatim to [`docs/how-it-works.md`](../how-it-works.md),**
with the Status narrative kept as Milestone 6 wrote it. Nothing in them is rewritten: each
`###` becomes `##` outside fences, each relative link is re-rooted, and one sentence that
said *"this README publishes"* now says *"this project publishes"*.

**A section's heading is its citation, so the move re-points the cases in the same change.**
The rule is mechanical — `README.md#what-makes-it-different/<section>/<n>` becomes
`docs/how-it-works.md#<section>/<n>`, because a document's H1 title is not part of an anchor —
and it is applied to the generator, from which both sets are regenerated. Three checks hold it:

1. **the same text** — every judged anchor was chunked before and after with the build's own
   parser, chunker and policy, and 25 of 26 distinct anchors resolve to text identical up to
   link targets. The 26th is the README's own comparison table, which stays, now followed by
   the index of the moved sections;
2. **the generator's own validation** — it builds the corpus and refuses a set with an
   unresolved anchor, and its output is byte-identical to the textual substitution;
3. **the gates** — every judged anchor is located in the self-hosting build.

This is a judgement file changing, and ADR-0027's rule allows it because nothing that ranks
changes with it: no tuning path is touched. It changes *where* a case's answer lives, not
*which* passage answers it.

**Settings the owner installs are drafted in code and reported.** The *About* description and
sixteen topics are `ABOUT_DESCRIPTION` and `ABOUT_TOPICS` in `tools/check_repo_settings.py`,
which now compares the live box with them; `docs/workflow/github-setup.md` §7 prints the two
commands, and a test holds the page and the constants to the same words. The *Website* field
waits for Pages: the docs-site address answers 404 until that owner step is done, so the README
no longer says the site is published on every push.

**The security policy states its response targets** — critical reports acknowledged within 24
hours and fixed or mitigated within 7 days, from v1.0.0 — which spec 06 §4 adopts at the point a
published compatibility promise makes them honest. For every other severity it promises
best-effort triage and says why: a single-maintainer project should not publish a target it
could not keep.

## Alternatives Considered

- **Leave the judged sections where they were and rewrite only the top.** Keeps every case
  untouched, and leaves a 600-line README whose middle a newcomer still scrolls past — the
  item half done. Offered to the maintainer and not chosen.
- **Two pull requests: reorder now, move the judged sections later.** Safer to review, and it
  leaves the README long until the second lands, while the second is exactly as risky as doing
  it now. Offered and not chosen.
- **Move the sections into the docs site.** The site is a separate source that joined the corpus
  only at roadmap 6.13, and ADR-0115 has it link out to `docs/` rather than hold the design
  record itself. `docs/` is already indexed and already where the ADRs the sections cite live.
- **Rewrite the moved sections while moving them.** Tempting, and it would have made the
  chunk-equality check meaningless: a move that also edits cannot show that each case still
  points at the passage it was judged on.
- **Set the About box from the agent.** It is a repository setting under the owner's account;
  ADR-0118's boundary is that the tool reports and the owner installs.

## Consequences

- A newcomer reaches Install in 45 lines and the security policy from a section heading.
- `docs/how-it-works.md` is the long-form account, and it says in its own header that its
  headings are citations — renaming one breaks every case pointing at it, which the generator
  refuses.
- The two cases that cite the README's comparison table now read a chunk that also carries the
  index of moved sections; the table is unchanged.
- `tools/check_repo_settings.py` reports one more absent setting until the owner runs §7.
- G2's recorded verdict carries a digest of the judged cases, so it is re-recorded in this
  change; no retrieval arithmetic moved.
