# mycelium-os v0.4.0

**Released:** 2026-09-09
**Milestone:** [4 — Ingestion (spec Phase 2)](../../ROADMAP.md#milestone-4--v02--ingestion-spec-phase-2) (declared scope complete)

## Highlights

v0.3.0 compiled the Markdown you wrote. **v0.4.0 compiles the documents you were given** —
PDF, DOCX, HTML and everything pandoc reads — into the same substrate, with the original bytes
kept, every element either represented or named as lost, and a citation that survives the trip.

```bash
mycelium ingest sources/handbook.pdf   # acquire -> custody -> KIR -> evidence/*.md
mycelium verify                        # grounding per candidate document (gate G7)
mycelium promote knowledge/candidate/retries.md
mycelium search "retry policy"         # the ingested document answers like any other
```

- **Ingestion, end to end.** Acquire under custody, parse through an adapter, account for
  what was lost, project a Markdown document the compiler picks up like any authored file.
  Four parsers behind two frozen Protocols — docling, pandoc, PDFium, markdown-it — pinned by
  configuration and never chosen for being available (ADR-0032).
- **Nothing is lost silently.** Every element is *represented*, *opaque*, *dropped by policy*,
  or *failed and reported*; a fidelity report counts them and a per-document loss budget can
  refuse the projection. The fixture corpus carries a hand-written inventory of what each
  source contains, so a parser that stops seeing tables fails a test rather than a review
  (ADR-0034, ADR-0043).
- **Hostile files quarantine, they do not stop the build.** Bounds are checked before an
  engine is asked to read: declared roots with no symlink escape, a byte ceiling checked
  against `stat`, decompression limits, a subprocess with `--sandbox` and a timeout. A source
  that fails is recorded, skipped and reported.
- **Secrets are found at ingestion**, flagged on the document and excluded from the index by
  default.
- **A synthesis lane that cannot make things up unpunished.** The `wiki` plugin authors
  candidate documents in which every claim-bearing block cites the evidence layer or nothing
  is written, and `mycelium verify` recomputes that coverage against the corpus *as it is* —
  so a candidate accepted in September stops verifying when the evidence it cites is deleted.
  Promotion stays a human action in Git.
- **The grep incumbent no longer wins.** This is Milestone 3's open item, closed. Measured on
  both sides at once, on the corpus this project did not write: **0.611 against 0.517**
  nDCG@10, and 0.637 against 0.478 on its ingested projection. What closed it was chunking and
  indexing — not any of the fourteen re-rankings that were proposed, measured and refused.
- **And the benchmark stopped flattering itself.** Cutting this release is what found it: this
  repository's own changelog and release notes were in the corpus it is evaluated on, and they
  restate what the ADRs already say in the same words — which costs a term-counting baseline
  far more than it costs us. Excluding them **narrows** our reported lead on our own release
  set from +0.218 to +0.186 (ADR-0072). Every release we had cut was widening that margin for a
  reason that had nothing to do with retrieval.
- **`mycelium eval --against grep` scores the incumbent inside the run**, on the same snapshot
  and the same cases, so the comparison cannot silently go stale again the way it did.

## What this release refuses to claim

Six changes were built or fully measured and left out. As in v0.3.0, this is the part most
worth reading, and each has an ADR saying what would change the answer:

| Refused | Why |
|---|---|
| Structured PDF via docling's ML pipeline | 2.4 GB and 3 s/page buy 82 % of headings **and a retrieval regression**: nDCG@10 0.398 → 0.327 on the PDF-answered cases (ADR-0040) |
| Hybrid retrieval as the default | Still unearned — and gate G2 now says it *cannot* be earned at these set sizes (ADR-0069) |
| A leaf-heading weight of 4.0 | The best row on one held-out set; below the baseline on dev and −18.1 % on `conceptual` on the other (ADR-0070) |
| A length split of the lexical index | Refused by the dev set, and the anti-correlation named (ADR-0066) |
| Loosening G2's per-slice bar so a candidate passes | The bar is catching real harm; the denominator is the fix, filed as 6.8 (ADR-0069) |
| Section-level scoring, and thirteen other re-rankings | Every one measured; the family's own ceiling is below what shipped (ADR-0031, ADR-0041, ADR-0049) |

## Known limitations

- **Gate G2 cannot promote hybrid retrieval, and that is now a stated property rather than a
  result.** Read case by case, its per-slice condition at four to seven cases a slice is a
  per-case veto: a typical losing case trips its slice on its own. So the lexical default rests
  on a burden that cannot currently be discharged. The bar was **not** moved to fix this; the
  denominator is filed as **6.8** (ADR-0069).
- **The `fact` slice on the second corpus is still the incumbent's** — 0.438 against grep's
  0.497, on seven cases, two of which carry it. The overall lead does not erase it.
- **PDF is a text layer.** No headings, no tables, no reading order, and a scanned page yields
  an opaque node saying so rather than an empty document pretending otherwise. The alternative
  was measured and is worse (ADR-0040).
- **Judgments are still not independent.** Nobody here wrote `uv`'s documentation, but the
  same agent that builds the retriever assigns the grades on all three corpora.
- **Ingestion is local.** One connector, the filesystem; remote sources are a later trust
  conversation.

## Upgrading from v0.3.0

The store's schema version moved **v3 → v5**, and a writer recreates a foreign store in
place — so the first `mycelium build` after upgrading rebuilds from source. That is the
declared migration policy (D-016), and it is safe because every row is derived from documents
you still have.

Retrieval changed, so **citations into an existing corpus may move**: the leaf heading is now
its own indexed field at weight 3.0, split from the ancestor chain (ADR-0063, ADR-0070). Nothing
about a document's identity changes; only the order results come back in.

Ingestion needs opting in. `pip install 'mycelium-os[ingest]'` brings the parsers, `pandoc`
3.x comes from your package manager, and `[ingest] parsers` pins which of them runs — the
default is `["markdown"]`, so a repository that only compiles Markdown is unaffected.

The package now advertises its types (PEP 561), so `mypy` will start checking your calls into
`mycelium`. That is the intent, and it may surface errors in code that previously resolved as
`Any`.
