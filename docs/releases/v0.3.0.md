# mycelium-os v0.3.0

**Released:** 2026-08-31
**Milestone:** [3 — The compiler (spec Phase 1)](../../ROADMAP.md#milestone-3--v01--the-compiler-spec-phase-1) (declared scope complete)

## Highlights

v0.2.0 compiled a repository once. **v0.3.0 compiles it incrementally, lets you go back, and
measures itself against a corpus it did not write** — and the most useful thing in it is a
list of changes that did *not* ship.

```bash
mycelium build --watch          # rebuild on save, with a manual build's guarantees
mycelium snapshots              # what has been published
mycelium rollback <id>          # restore, then repoint
mycelium export                 # a JSONL bundle whoever receives it can verify
mycelium eval . --gate          # the gates, in CI
```

- **Incremental compilation.** A build recompiles the documents that changed, through a
  content-addressed stage cache keyed on what each stage actually reads. 200 documents: cold
  12.9 s, no-op 452 ms, single edit 546 ms — and an incremental build is byte-equal to a clean
  one by tested construction (ADR-0015).
- **Snapshots you can go back to.** Every publication writes the build's whole state as one
  content-addressed blob, so `rollback` **restores and then repoints** rather than moving a
  pointer over data that no longer matches it. Garbage collection has a defined live set and
  two dials, because one of them alone collects nothing (ADR-0016).
- **Watch mode that does not trust events.** Filesystem events decide *when* to build; the
  build decides *what*. Every platform reports a build's own reads as events by some route, so
  a change is proved against the store before a rebuild runs (ADR-0019).
- **A vector leg, switched off.** A local ONNX embedder, vectors keyed `(chunk_digest,
  model_id)`, RRF fusion — and gate G2 saying hybrid has **not** earned the default. It is one
  setting away, and the README says why it is not the default (ADR-0017).
- **Retrieval that abstains.** Hybrid used to answer every unanswerable query, because cosine
  similarity ranks everything. Lexical evidence is now the vector leg's precondition: hybrid
  abstains exactly where the gated baseline abstains, by construction rather than by a
  calibrated constant (ADR-0025).
- **Queries that meet their budget.** The vectors are packed into one memory-mapped matrix per
  model: a query over 10 000 chunks went from 92.97 ms to **2.88 ms**, and the scan stays
  *exact* — four ways of not reading every vector were measured and all four refused
  (ADR-0026, ADR-0028, ADR-0031).
- **An evaluation that can catch us.** Two corpora — this project's documentation and `uv`'s,
  vendored and pinned, written by people who never saw this code — 62 judged cases, a
  dev/release split, and gates in CI. On its first real use the split caught an overfit that
  improved both dev sets and regressed the held-out one (ADR-0027).

## What this release refuses to claim

Four changes were built, measured, and left out. They are the part of this release most worth
reading, and each has an ADR that says what would change the answer:

| Refused | Why |
|---|---|
| Hybrid retrieval as the default | +12.7 % nDCG overall, but −17.8 % on the `exact` slice (ADR-0017) |
| A similarity floor for abstention | Near-domain unanswerable probes score *inside* the answerable band (ADR-0025) |
| An approximate vector index | Everything fast enough returns a third to three quarters of the answer (ADR-0028) |
| Three re-rankings of the lexical leg | Two trade one corpus for the other; the third failed gate G3 on the held-out set (ADR-0031) |

## Known limitations

- **The grep incumbent still beats the product on the second corpus** — nDCG@10 0.471 against
  0.280 — while the product wins Recall@50 and answers in 14 ms against 195. The right passages
  are retrieved and ranked below the wrong ones, and the cause is measured: BM25 normalises by
  document length and our chunks are wildly heterogeneous. Filed during Milestone 3 and
  **carried into Milestone 4 as item 4.8** rather than closed to make a milestone look
  finished — M3's declared scope was items 3.1–3.7, and this was found by the work itself.
- **Judgments are not independent.** Nobody here wrote `uv`'s documentation, but the same agent
  that builds the retriever still assigns the grades on both corpora.
- **Ingestion is Milestone 4.** Every document this version compiles is authored Markdown.

## Upgrading from v0.2.0

The store's schema version changed, and a writer **recreates a foreign store in place** — so
the first `mycelium build` after upgrading rebuilds from source. That is the declared migration
policy (D-016), and it is safe because every row is derived from documents you still have.
Commit the `mycelium_id` frontmatter the build pins, as before.

`[chunking] target_tokens` is honoured now, where it was accepted and ignored. If your
`mycelium.toml` sets it below `max_tokens`, chunk boundaries will move and citations into that
corpus will change — the default is unchanged, so leaving it unset changes nothing (ADR-0023).
