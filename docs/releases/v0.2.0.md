# mycelium-os v0.2.0

**Released:** 2026-08-30
**Milestone:** [2 — Walking skeleton (spec Phase 0)](../../ROADMAP.md#milestone-2--walking-skeleton-spec-phase-0) (complete)

## Highlights

v0.1.0 proved the repository was buildable. **v0.2.0 is the first release that does the
thing**: it compiles a repository's Markdown into a deterministic, versioned, queryable
snapshot and serves it to an agent with citations.

```bash
mycelium init && mycelium build
mycelium search "retry policy"
mycelium serve            # read-only MCP over stdio, for your agent
```

- **The compiler.** Markdown → KIR → heading-bounded chunks → SQLite, published as an
  immutable snapshot with an atomic `CURRENT` pointer swap. Readers never observe a torn
  state, and an interrupted build leaves the previous snapshot untouched.
- **Citations that survive edits.** `mycelium://<doc-id>#<heading-path>/<ordinal>` keys on
  document identity, not path, so a citation outlives a rename or a folder move. The first
  build pins a `mycelium_id` into each document's frontmatter — commit those files.
- **Two public surfaces.** The `mycelium` CLI (`init`, `build`, `search`, `show`, `doctor`,
  `eval`, `serve`) with `--json` on every read command and 0/1/2 exit codes; and an MCP
  stdio server exposing `mycelium_search` and `mycelium_fetch`, read-only.
- **Determinism is gated, not asserted.** Gate G6 rebuilds a fixture corpus in CI and
  compares it against a reviewable golden — per-chunk detail, not one hash — so any change
  to compiler output shows up in a diff a reviewer can read.
- **Quality is measured against the incumbent.** The evaluation harness ships with 20
  judged cases over this repository's own docs and runs the agent's own `grep` as the
  baseline to beat.
- **Configurable.** `mycelium.toml` is read and validated with precise errors; settings the
  engine cannot honour yet are accepted, digested, and named by `mycelium doctor` rather
  than silently ignored.

## First measured numbers

On the 20-case seed set over this repository's documentation:

| | Mycelium | grep | |
|---|---|---|---|
| nDCG@10 | 0.70 | 0.55 | +26 % |
| MRR | 0.83 | 0.62 | +35 % |
| p95 latency | 3 ms | 52 ms | 17× |

Gates G1 (citation coverage 1.00) and G4 (no invented matches) pass. The weak slices are
published with the strong ones: `relationship` scores 0.32 because the typed edge graph does
not exist until milestone 5, and `conceptual` 0.66, barely ahead of grep — which is exactly
the gap hybrid retrieval must close to earn G2 at milestone 3. The judgments were assigned
by the agent that wrote most of the documents being judged; that limitation is recorded in
[`eval/README.md`](../../eval/README.md) and in [ADR-0013](../adr/0013-adopt-the-evaluation-harness.md).

## Known limits

This is a walking skeleton, and the skeleton's shape is deliberate:

- **Every build is a full rebuild.** The content-addressed incremental DAG is milestone 3;
  build keys and the cache do not exist yet.
- **Retrieval is lexical only.** No embeddings, no hybrid fusion, no graph expansion —
  `[embedding]` is recorded in the manifest but not honoured until milestone 3.
- **Markdown only.** PDF/DOCX/HTML ingestion is milestone 4; `[ingest]` and `[sources]` are
  accepted but inert.
- **Two MCP tools, not four.** `mycelium_neighbors` needs the edge graph (milestone 5) and
  `mycelium_explain` needs hybrid retrieval (milestone 3).
- **`[chunking] target_tokens` is advisory.** The packer fills toward `max_tokens`; making
  the target steer chunk size is filed as roadmap 3.8 because it moves every boundary and
  needs eval numbers beside it.

`mycelium doctor` names the sections of your config that do nothing yet, so the limits are
visible from inside the tool as well as from these notes.

## Upgrading

There is no data migration: the derived store under `.mycelium/` is disposable by design
(v1 migration policy is **rebuild**, D-016). If you built anything with a pre-release
revision, delete `.mycelium/` and run `mycelium build` again.

```bash
uv sync --all-extras --dev
uv run pytest -q
```

Note that snapshots built by earlier revisions carry a different `config_digest`: the field
now digests the effective configuration rather than a placeholder. Chunk content is
unchanged.
