# mycelium-os v0.6.0

**Released:** 2026-09-23
**Milestone:** [6 — Stable (spec Phase 4)](../../ROADMAP.md#milestone-6--v060--stable-spec-phase-4) (gates G1–G7 green and the compatibility promise published; the external-adoption gate unmet and carried by name)

## Highlights

v0.5.0 gave what the compiler produces a *structure*. **v0.6.0 makes it stable, packaged, and
honest about itself** — the contracts stop moving, the artifact becomes a defined thing, and a
great deal of what was measured this milestone turned out to be worth refusing.

- **The five contracts are frozen.** Identity, KIR, the snapshot manifest, the MCP tools and the
  plugin protocols each have a golden of their shape and a test that fails when it moves. What is
  promised — from which version, and how a change to it is made — is written down in
  [`docs/compatibility.md`](../compatibility.md), published *before* the tag that begins promising
  it (ADR-0114).
- **The artifact is a defined thing.** The build signs and inventories what it produces, and the
  publish workflow runs on `workflow_dispatch` only, inside an environment with required
  reviewers, re-checking that the tag equals the declared version before it uploads — because a
  published version is immutable (ADR-0116, ADR-0117).
- **The threat model became a test suite.** Injection resistance, and a bound on what a single
  document may cost to read, are now properties the suite asserts rather than intentions
  (ADR-0119).
- **The docs site is built, checked and deployed**, and the plugin cookiecutter is rendered in CI
  to prove it still produces something that works (ADR-0115, ADR-0127).
- **A published benchmark report with run manifests**, and the reference profile the latency
  budgets are stated against (ADR-0120).

## What got faster, and by how much

Every number below is end-to-end on the machine of record, with the benchmark committed beside
the change:

| what | before | after |
|---|---:|---:|
| `mycelium --version`, no module installed | 2 454 ms | **1 057 ms** (−56.9 %) |
| `import mycelium.cli.app` | 1 894 ms / 481 modules | **420 ms / 164 modules** |
| `handle_search` constant (config + entry-point scan) | 302 ms | **45 ms** |
| cold build, 1 000 documents (roadmap 6.19) | 193.5 s | **91.7 s** |
| the `symbols` stage of a no-op rebuild | 250 ms | **188 ms** |

Cost per document went from *rising* with corpus size — 134 ms at 250 documents, 194 ms at 998 —
to **flat at ~92 ms**, which was the quadratic the item was filed for. Spec 01 §8's *cold build
1 000 docs < 60 s* is still missed, and saying so is the point of measuring it.

The configuration fix is the one worth reading twice: `load_config()` was calling
`importlib.metadata.entry_points()`, which re-reads every installed distribution's metadata, on
**every tool call** — 262 ms against a 150 ms budget for the whole call. Two of the filing item's
own explanations for it turned out to be wrong, and were corrected by measuring them (ADR-0128).

## What was measured and refused

This is the larger half of the milestone. Each row is an ADR with the arithmetic in it and a
runner on CI that fails the day the refusal stops being true:

| candidate | verdict | where |
|---|---|---|
| per-document diversity / MMR | every cap and every decay loses on every release set | ADR-0144 |
| heading-proximity boost | none of 96 arms gains; the family's optimum is the shipped ranking | ADR-0153 |
| `trust_class` / verification / recency boosts | inert by arithmetic — every corpus is single-valued in the field they read | ADR-0153 |
| near-duplicate collapse | zero occasions in the shipped ten, on all six sets | ADR-0153 |
| a second config cache | 2.1 ms once the first one landed — buys nothing, costs an invalidation question | ADR-0128 |

Two results from that work are worth stating on their own. **Re-ordering the same fifty
candidates by their judged grade is worth +36 % to +91 %** — far more than any leg or boost this
project has shipped or refused — and **58–72 % of that is reachable by permuting the ten results
already returned**, with no new candidate at all (ADR-0152). And spec 06 §3's learned-reranker
trigger is explicitly **not** declared met: what was established is that the headroom is reachable
by re-ordering, not that no deterministic rule can reach it, and no deterministic re-ordering of
the served set has ever been tried. A family with no attempts in it has not plateaued.

Spec 04 §4 was **amended rather than trimmed**: each rule it describes now records what was
measured and what ships, so a reader of the specification learns that a sentence is not the
product without having to find the ADR.

## Measured

Release sets — the ones nobody develops against — scored against the agent's own `grep` loop,
which is the bar D-010 sets:

| release set | Mycelium OS | the `grep` loop |
|---|---:|---:|
| `uv`'s documentation | **0.690** | 0.562 |
| the same documents, ingested from DOCX/HTML/PDF | **0.648** | 0.581 |
| this repository, measured at the cut | **0.474** | 0.244 |

**These are not comparable with v0.5.0's table, and the reason is this milestone's own work.**
Roadmap 6.8 re-authored all three release sets at ten to sixteen times their size, and 6.33 did
the same for the dev sets, so the instrument changed underneath the numbers. The judged sets now
hold **2 001 cases across six sets** against spec 04 §7.6's target of 1 000. A score measured on
286 questions is a different statement from one measured on 20, and reading a fall from 0.521 to
0.474 as a regression would be reading two different instruments as one.

On the agent-task suite — twenty-two tasks judged on documentation this project did not write —
Mycelium OS finds the evidence on **73 %** against `grep`'s 64 %, and spends **3.8× less context**
doing it.

## Known limits

- **External adoption stands at zero.** Milestone 6's exit gate — three external authors of two
  merged pull requests each, and one `contrib/` module authored outside the maintainer — is unmet
  and carried by name rather than waived, with the blocker underneath it unchanged: the package
  is built, signed and inventoried, and the publish workflow exists, but nothing is published to
  a public index yet (roadmap 6.11, 6.12; ADR-0138).
- **Hybrid retrieval stays off.** It still cannot clear gate G2's bar on these sets, so the
  lexical default stands — the bar is not moved to fit a candidate.
- **Query latency at scale is unsolved.** At the 10⁵-chunk reference profile the warm query is
  2 349.7 ms p95 against a 150 ms budget, and candidate generation is 99.9 % of it. The constant
  cost is fixed; the scaling is not, and it is the honest headline of the benchmark report.
- **Stitching is unbuilt and undecided** — the one spec 04 §4 rule neither shipped nor refused,
  because nDCG punishes collapsing a result slot on principle and the claim under it is about
  comprehension. It goes to the agent-task suite rather than being guessed at.

## Upgrading

Nothing is required of you: the store is derived data and rebuilds itself. The version constant
moves to 0.6.0 and the compatibility promise begins applying from this release — see
[`docs/compatibility.md`](../compatibility.md) for what is promised and how a change to it is
made.

**How to install, honestly:** from the wheel or sdist attached to this release, or from a clone
with `uv sync --all-extras --dev`. `mycelium-os` is **not on a public package index yet** — the
release workflow builds, signs and attaches the artifacts, and the publish workflow is run by
hand against TestPyPI — so the `pip install mycelium-os[…]` lines elsewhere in the documentation
still describe an intended future rather than today.
